# 需求文档：AgentFarm2 可玩性升级（旗舰版）

Feature Name: agentfarm2-playability-upgrade
Updated: 2026-09-28
Edition: Flagship（全量最高规格，无降级取舍）
Status: 规划（本轮不施工）

## Introduction

本需求覆盖让 AgentFarm2 达到"长期好玩、可对外发布"水准的全部七个工作流，每个工作流按当前技术条件下最优路线规划，接受更高的工程量与运行成本：

- M1 旁观体验层：导演镜头、想法气泡、AI 画报日报、事件溯源回放
- M2 深度市场经济：连续双边拍卖订单簿、库存型 NPC 商人、经济遥测
- M3 全场景权威导航：27 场景分层寻路 + NPC 日程系统
- M4 Agent 认知系统：三层记忆、OCC 情感模型、目标层级、八卦传播
- M5 内容扩展与旗舰美术管线：季节天气节日动物家具烹饪 + 提示词工程生图与 CC0 三管线
- M6 工程地基：TypeScript 重写、事件溯源、CI、可观测性、部署
- M7 LLM 接入与治理：玩家自带 Key、双档模型路由、缓存、计量

用户约束：客户端保持"原版外壳"策略，新增视觉经 mod 注入层渲染；美术资产由"参考图编辑生图 + 调色板量化 + CC0 直采"三管线供给；一切状态可回放。

## Glossary

- **事件溯源**：世界全部状态变更以不可变事件序列记录，任意时刻状态可由事件回放重建。
- **导演镜头**：客户端观战模式，服务器按"事件热度"调度玩家相机跟随最有戏剧性的 Agent。
- **连续双边拍卖（CDA）**：买卖双方挂单撮合的订单簿市场，价格由成交记录连续形成。
- **NPC 商人**：持有库存与现金的自治商人实体，低买高卖、跨场景跑单，用导航系统移动。
- **分层寻路（HPA*）**：先在场景间图上规划粗路径，再在场景内网格精化的两级 A*。
- **三层记忆**：L1 工作上下文（决策窗口内）、L2 情节记忆流（可检索经历）、L3 语义知识图谱（时序事实三元组）。
- **OCC 情感模型**：Ortony-Clore-Collins 认知情感模型，由事件评价推导 22 类情感强度，驱动行为权重与语气。
- **睡眠期整理**：利用 Agent 空闲时段运行的后台整理任务，执行记忆压缩、反思、关系摘要与图谱清洗。
- **风格提示词库**：版本化管理的风格描述模板与调色板资产，使生图输出贴合原版画风。
- **参考图编辑生图**：以原版 sprite 为参考图驱动生图模型改绘新资产的生成方式。
- **双档模型路由**：按任务类型将请求分流到玩家自配的轻量/强力两档模型，Key 由玩家自带。

## Requirements

### R1 旁观体验层（M1）

**User Story:** AS 玩家, I want 像看真人秀一样观察 Agent 生活, so that 观察本身构成核心游戏乐趣。

#### Acceptance Criteria

1. WHEN Agent 产生新的行动计划，系统应将该计划文本经 WebSocket 推送到同场景客户端，并在该 Agent 头顶渲染想法气泡，显示 6 秒。
2. WHEN 服务器判定某事件的观赛热度超过当前跟随目标，导演镜头应在 3 秒内将观战玩家相机平滑切换到热度最高的事件现场。
3. WHILE 观战模式开启，系统应提供自由镜头与导演模式两种状态，玩家切换后相机控制权即时移交。
4. WHEN 游戏日切换，系统应调用 LLM 按当日事件生成一篇画报日报，日报含标题、导语、至少 3 个栏目、2 幅 AI 插画与市场行情栏。
5. WHEN 画报插画生成失败或审核未过，系统应改用当日事件现场的服务器截图作为配图。
6. WHEN 事件重要性评分达到 8 以上，系统应立即向全体在线玩家推送高光弹幕并写入高光索引。
7. WHEN 玩家打开高光回放，系统应基于事件溯源日志确定性重放该事件发生前后的完整状态序列，重放进度条支持拖动。
8. WHEN 玩家回放任意历史片段，重放结果中的实体位置、物品数量与当日存档快照的差异应为零。

### R2 深度市场经济（M2）

**User Story:** AS 商人人设的 Agent 或玩家, I want 一个真实运转的市场, so that 套利、囤积、定价成为有深度的核心玩法。

#### Acceptance Criteria

1. WHEN 玩家或 Agent 挂出买单或卖单，系统应将订单写入连续双边拍卖订单簿，并按价格优先、时间优先规则即时撮合。
2. WHEN 订单簿产生成交，系统应以成交价更新该物品的市场价序列，并广播成交通知给买卖双方。
3. WHEN 卖方挂牌价高于当前最高买价 30%，系统应将该订单标记为"虚高"并在观察文本中向 Agent 提示流动性风险。
4. WHILE NPC 商人处于营业状态，系统应使其依据自身库存、现金与最近 7 日价格序列自主决策买卖，利润留存于其账户。
5. WHEN NPC 商人决定前往另一场景采购，系统应使用导航系统生成完整移动路线并逐段执行。
6. WHEN 游戏日结束，系统应输出经济日报：各物品 OHLC 价格、成交量、货币总量、通胀指数（当日价格中位数环比）。
7. WHEN 通胀指数连续 3 日超过 1.1，系统应自动启用货币回收机制（提升建筑造价与NPC服务费）并在日报中公告。
8. WHEN 玩家或 Agent 执行 game_observe，观察文本应包含订单簿快照：前 5 档买卖价、量与最近 10 笔成交。
9. WHEN 市场开启影子模式，真实结算价格与影子模拟价格应并行记录 14 日并输出对比报告。

### R3 全场景权威导航与 NPC 日程（M3）

**User Story:** AS 任意人设的 Agent 或 NPC, I want 跨全部 27 张场景的稳定移动, so that 探索、跑商、NPC 生活节奏全部成立。

#### Acceptance Criteria

1. WHEN 服务器启动，系统应为全部场景各生成一张权威导航网格，每格含 blocked、kind、cost、clearance 四字段，并构建场景间门户图。
2. WHEN 收到跨场景 move_to 请求，系统应先在门户图上做粗规划，再逐场景做网格级 A* 精规划，输出场景序列与每段航点。
3. WHEN 客户端到达一个航点，系统应校验真实落点偏差，超过半格即从真实位置重新规划剩余路径。
4. WHILE Agent 或 NPC 跨场景移动，系统应在场景切换完成事件到达后才开始下发下一段航点。
5. WHEN 玩家打断 Agent，系统应在 200ms 内停止航点下发并置状态为 STAND。
6. WHEN 游戏时间到达 NPC 日程表条目时刻，系统应使用同一导航系统将对应 NPC 移动到日程目标位置。
7. WHEN NPC 日程表生成，系统应保证 NPC 在节日期间聚集于集市、雨天聚集于室内、夜晚归家。
8. WHEN 从任意宅基地到河边、村中心、矿点、邻近场景的路线连续执行 10 次，系统应保证到达同一交互环且零卡死、零坐标漂移。

### R4 Agent 认知系统（M4）

**User Story:** AS Agent, I want 完整的记忆、情感与目标体系, so that 我的性格在长期生活中持续生长且有迹可循。

#### Acceptance Criteria

1. WHEN Agent 经历一次观察、行动或对话，系统应将事件写入 L2 情节记忆流，并抽取时序事实三元组写入 L3 知识图谱（含生效时间与失效时间）。
2. WHEN Agent 决策，系统应按新近度、相关度（embedding 余弦）、重要性三因子召回前 10 条 L2 记忆，并从 L3 图谱查询当前有效的相关事实注入上下文。
3. WHEN Agent 情节记忆超过 50 条或进入睡眠期，系统应运行整理任务：归纳反思条目、压缩低重要性记忆、修订图谱失效事实。
4. WHEN 事件被评价模块处理，系统应按 OCC 模型更新该 Agent 的情感向量，情感强度随时间指数衰减（半衰期 1 游戏日）。
5. WHILE 情感向量中喜悦、愤怒任一分量超过阈值，系统应调整该 Agent 的行为权重与语气模板并在想法气泡中体现情绪。
6. WHEN Agent 维护目标层级，系统应同时持有长期人生目标（人设派生）、中期计划（每日刷新）与短期动作，高层目标变化应级联标注到受影响的下层目标。
7. WHEN Agent 与对象的好感累计变化超过 10 点，系统应生成八卦事件，经聊天通道传播给可信对象，传播内容随链路长度逐级衰减细节。
8. WHEN 两个 Agent 对话，系统应保证双方引用彼此的历史记忆（上次见面事件、共同经历）的比例不低于对话轮次的 30%。
9. IF 记忆存储损坏，系统应从最近备份恢复，备份间隔为 1 游戏日且保留 7 份。

### R5 内容扩展与旗舰美术管线（M5）

**User Story:** AS 玩家或 Agent, I want 季节、节日、畜牧、家具与烹饪构成的完整生活世界, so that 每种人设都有专属的生活方式可演绎。

#### Acceptance Criteria

1. WHEN 游戏日推进满 10 天，系统应切换季节，季节决定作物生长系数（春 1.1/夏 1.0/秋 0.9/冬 0.3）、可种作物白名单与地图色调滤镜。
2. WHEN 每个游戏日 6 点，系统按季节权重决定天气（晴/雨/雪/风暴），雨天作物免浇水且生长 1.5 倍，风暴损坏露天作物 20%。
3. WHEN 季节性节日到来（春夏秋冬各一场），系统应生成节日集市场景、专属活动（钓鱼大赛/丰收评比/雪雕/花会）与限定商品。
4. WHEN 玩家或 Agent 参加节日比赛，系统应按规则判定名次、发放限定奖励并写入高光与日报。
5. WHEN 动物（鸡/羊/牛/猪）被饲养，系统应模拟饱食度、心情与产出品质，产出分为普通/银/金三档并影响售价。
6. WHEN 烹饪或加工完成（磨坊/厨房/窑炉），系统应按配方表将原料转化为成品，成品价格高于原料简单相加。
7. WHEN 家具被放置到宅基地布置点，系统应写入装饰数据、经 mod 层渲染，并计入装饰完成度。
8. WHEN 装饰完成度达到 100%，系统应调用视觉模型对宅基地截图评分并举办"最美庭院"评比，结果进入日报。
9. WHEN 新美术资产进入游戏，系统应保证其来源于三管线之一：参考图编辑生图（原版 sprite 作参考 + 风格提示词库）、文生图 + 调色板量化、CC0 直采，且全部经人工送审。
10. WHEN 风格提示词库新增或修改风格条目，系统应在固定测试资产集上输出对比样张，人工评分达标（原版风格相似度主观分 >= 4/5）后方可投产。

### R6 工程地基（M6）

**User Story:** AS 开发者, I want 类型安全、可回放、可观测、可部署的服务端, so that 全部玩法功能建立在长期可维护的地基上。

#### Acceptance Criteria

1. WHEN 服务端重构完成，系统应以 TypeScript 实现模块化架构（网关/世界/市场/导航/认知/叙事/持久化七模块），开启 strict 模式，构建零类型错误。
2. WHEN 任意世界状态变更发生，系统应先追加事件到事件日志再应用状态，事件日志为唯一事实来源。
3. WHEN 服务进程重启，系统应通过重放事件日志恢复状态，并提供快照点以将恢复时间控制在 10 秒内。
4. WHEN CI 运行，系统应执行：类型检查、单元测试、协议回归测试、秘密扫描、原版文件哈希校验，任一失败即阻断合并。
5. WHEN 敏感配置加载，系统应从环境变量读取，缺失时启动失败并列出缺失项。
6. WHILE 服务运行，系统应输出结构化日志（pino）与关键指标（每模块耗时、事件吞吐、LLM 用量），并提供管理后台页面查看。
7. WHEN 部署执行，系统应通过 Docker 镜像发布到 fly.io，staging 与生产环境分离，数据库每日自动备份且保留 30 天。
8. WHEN 任意提交引入 client/game/ 目录变更，CI 应阻断并提示维持原版零改动约束。

### R7 LLM 接入与治理（玩家自带 Key）

**User Story:** AS 玩家, I want 用自己的模型 Key 驱动我的 Agent, so that 我获得旗舰认知体验且服务端零模型成本。

#### Acceptance Criteria

1. WHEN 玩家在账号设置提交模型配置（API 地址、Key、模型名、双档映射），系统应加密存储，并在 Agent 子进程启动时以环境变量注入。
2. WHILE Agent 运行，系统应只使用该账号绑定的 Key 调用模型，服务端应绝不持有或共用任何池化密钥。
3. WHEN 玩家未配置 Key 或 Key 连续 3 次鉴权失败，系统应将该 Agent 切入规则脚本降级模式并显示"降级运行"。
4. WHEN 玩家更新 Key 或 Key 恢复有效，系统应在该 Agent 下一决策周期切回模型模式。
5. WHEN 玩家打开 Agent 面板，系统应展示本人 Agent 的用量统计（调用次数、token 数、按玩家自报单价折算的参考成本）。
6. WHEN 相同前缀上下文在 10 分钟内重复出现，系统应命中本地结果缓存以减少玩家 Key 消耗。
7. WHEN 玩家配置双档映射，系统应按任务类型路由：感知摘要/打分/抽取走轻量档，规划/对话/创作走强力档；未配置映射时全部请求走单一模型。

## Non-Functional Requirements

- 性能：8 玩家 + 8 Agent 在线，game_observe P95 延迟不超过 800ms，事件吞吐峰值 200 事件/秒。
- 回放确定性：同一事件日志在不同机器重放，最终状态哈希一致。
- 兼容：client/game/ 目录零改动，全部视觉经 mod 注入层；NPC 与新实体渲染使用 mod 层统一 sprite 管线。
- 许可：全部第三方资产写入 LICENSES 目录；CC-BY-SA 类素材仅在资产独立打包路径确认后引入；AI 生成资产保留生成参数留档。
- 成本：运行期现金成本为零——LLM 由玩家自带 Key，美术资产在开发期以内置生图工具产出并入库，托管采用本地部署 + Tailscale 联机或免费云档。
