# 需求文档：AgentFarm2 可玩性升级

Feature Name: agentfarm2-playability-upgrade
Updated: 2026-09-28
Status: 规划（本轮不施工）

## Introduction

本需求覆盖让 AgentFarm2 从"可玩原型"进化为"长期好玩"的六个工作流：

- M1 旁观体验层：想法气泡、村庄日报、高光时刻
- M2 动态市场经济：供需价格、倒卖空间、市场行情
- M3 权威导航图与跨场景移动（承接 docs/最终版规划书.md）
- M4 Agent 记忆与关系系统：情节记忆、反思、Agent 间关系网络
- M5 内容机制扩展：天气/季节/节日/动物/家具装饰，含美术资产管线
- M6 工程地基：服务端模块化、持久化升级、凭据安全、LLM 降级

用户已确认约束：客户端保持"原版外壳"策略，新增视觉通过 mod 注入层叠加；新美术资产由开源 CC0 素材 + 生图模型两条管线供给。

## Glossary

- **世界事件**：服务器模拟产生的状态变化记录（收获/交易/聊天/天气/节日），带时间戳与参与者。
- **想法气泡**：客户端在 Agent 头顶渲染的短期意图文本，来源为 Agent 决策日志的当前计划。
- **村庄日报**：每个游戏日结束时由服务器聚合世界事件自动生成的叙事文档。
- **动态市场**：物品价格随全服供需变化的定价系统，基价由 items.json 提供，供需因子周期性回归。
- **权威导航图**：单一来源的 105x89 格导航数据（blocked/kind/cost/clearance），服务端寻路、客户端碰撞、Agent 观察均由其派生。
- **情节记忆**：Agent 可检索的过往经历条目（观察/行动/结果），按新近度+相关度+重要性评分召回。
- **关系网络**：Agent 与玩家、Agent 与 Agent 之间的好感、人情、恩怨记录，可被八卦事件修改。
- **美术资产管线**：从 CC0 素材库下载 + 生图模型生成，经调色板对齐与人工修整后进入游戏的流程。

## Requirements

### R1 旁观体验层（M1）

**User Story:** AS 玩家, I want 实时看到 Agent 的想法和村庄里发生的趣事, so that 观察本身成为游戏乐趣。

#### Acceptance Criteria

1. WHEN Agent 产生新的行动计划，系统应将当前计划文本推送到同场景玩家客户端，并在该 Agent 头顶渲染想法气泡，气泡显示时长为 6 秒。
2. WHILE 想法气泡处于显示状态，系统应在气泡内容更新时立即替换文本并重置 6 秒计时。
3. WHEN 游戏日切换（1 游戏天 = 10 分钟真实时间），系统应从世界事件日志聚合生成一篇村庄日报，日报包含当日事件条目、参与者、金币流水摘要与天气，条目数上限 30 条。
4. WHEN 玩家点击日记按钮，系统应在现有日记面板旁提供"村闻"页签，展示最近 7 个游戏日的日报。
5. IF 当日世界事件为空，系统应生成包含天气与在线人数的极简日报。
6. WHEN 服务器检测到事件重要性评分超过阈值（如首次捕获稀有鱼、单笔交易额超过 500 金币、好感度跨越关系等级），系统应立即向全体在线玩家推送高光弹幕。

### R2 动态市场经济（M2）

**User Story:** AS 商人人设的 Agent 或玩家, I want 物品价格随供需波动, so that 低买高卖、囤积倒卖成为有深度的玩法。

#### Acceptance Criteria

1. WHEN 任意卖出交易完成，系统应将对应物品的供需因子向"供应过剩"方向调整，调整幅度为交易量的线性函数。
2. WHEN 任意买入交易完成，系统应将对应物品的供需因子向"供不应求"方向调整。
3. WHILE 供需因子偏离基线，系统应按每游戏小时 5% 的速率将其向基线 1.0 回归。
4. WHEN NPC 收购某物品，实际收购价应等于 items.json 基价乘以该物品供需因子，结果四舍五入到整数金币。
5. WHEN Agent 或玩家执行 game_observe，观察文本应包含当前市场行情表（至少：每种可交易物品的基价、现价、今日涨跌幅）。
6. IF 某物品供需因子超出 [0.3, 3.0] 区间，系统应将其截断到边界值。
7. WHEN 系统生成村庄日报，日报应包含当日涨幅前三与跌幅前三的物品。

### R3 权威导航图与跨场景（M3）

**User Story:** AS 任意人设的 Agent, I want 稳定的寻路与跨场景移动, so that 探险家人设可以远行且所有 Agent 不再卡树。

#### Acceptance Criteria

1. WHEN 服务器启动，系统应从村庄地图数据、建筑矩形、树丛区域生成 navigation-grid.json，网格尺寸 105x89，每格含 blocked、kind、cost、clearance 四个字段。
2. WHEN 收到 move_to 请求，系统应在权威导航图上以 A* 规划完整路径，并将路径压缩为航点序列下发。
3. WHEN 客户端到达一个航点，系统应校验真实落点与规划落点偏差，偏差超过半格时从真实位置重新规划。
4. WHEN 目标坐标位于其他场景，系统应先通过原版场景切换通道加载目标场景，场景加载完成后重新执行本场景内规划。
5. WHEN 玩家打断 Agent，系统应在 200ms 内停止下发航点，并将 Agent 状态置为 STAND。
6. WHILE 权威导航图存在，系统应以该图为唯一寻路依据，客户端碰撞注入与 Agent 观察文本均从同一份数据派生。
7. WHEN 从任意宅基地到河边、村中心、矿点的路线连续执行 10 次，系统应保证每次到达同一交互环且无卡死、无坐标漂移。

### R4 Agent 记忆与关系系统（M4）

**User Story:** AS Agent, I want 记住重要经历并维护与他人的关系, so that 行为有连续性、个性有厚度。

#### Acceptance Criteria

1. WHEN Agent 完成一次行动或收到一条聊天，系统应将该事件写入该 Agent 的情节记忆流，条目包含时间戳、类型、文本、参与者与重要性评分（1-10）。
2. WHEN Agent 需要决策，系统应按新近度、相关度、重要性加权评分召回前 10 条记忆并注入决策上下文，权重比为 1:1:1，可在配置中调整。
3. WHEN 累计记忆条目数超过 50 条，系统应触发一次反思，将相近记忆归纳为 1-3 条高层结论并写入记忆流，重要性评分不低于 7。
4. WHEN Agent 与同一对象的好感度变化累计超过 10 点，系统应将关系变化写入关系网络并向对方 Agent 传播一条八卦消息。
5. WHEN Agent 收到八卦消息，系统应将八卦内容写入自己的记忆流并按说话者可信度调整对被谈论者的好感预判。
6. IF Agent 记忆存储损坏，系统应从最近一次自动备份恢复，备份间隔为 1 游戏天。
7. WHEN 玩家打断 Agent 正在执行的人设倾向行为，系统应将该打断事件以重要性 8 写入记忆流，供后续反思生成情绪结论。

### R5 内容机制扩展与美术管线（M5）

**User Story:** AS 玩家或 Agent, I want 天气、季节、节日、动物与家具装饰, so that 人设承诺的行为（装饰、收集、节庆社交）有真实机制承接。

#### Acceptance Criteria

1. WHEN 游戏日推进满 10 天，系统应切换到下一季节，季节影响当日作物生长速度（春 1.1x、夏 1.0x、秋 0.9x、冬 0.3x）。
2. WHEN 每个游戏日 6 点，系统应按季节权重随机决定当日天气（晴/雨/雪），雨天应使所有已种植作物生长速度提升 1.5x 且免除人工浇水。
3. WHEN 当日为节日（每月第 10 天为丰收节、第 20 天为集市日），系统应广播节日公告并在村中心生成节日集市场景。
4. WHILE 集市日，系统应允许玩家与 Agent 在村中心摆摊，摊位价格由摆摊者自定，交易走动态市场管线。
5. WHEN 玩家或 Agent 购买动物幼崽（鸡/羊/牛）并放入畜棚，系统应按游戏日产出蛋/羊毛/牛奶，动物饱食度低于 20 时停止产出。
6. WHEN 玩家或 Agent 在自家宅基地执行放置家具动作，系统应将该家具写入宅基地装饰数据并在客户端 mod 层渲染。
7. WHEN 新增美术资产，系统应通过两条管线供给：CC0 素材库直采，或生图模型生成后经调色板对齐与人工修整。
8. IF 生图资产与原版调色板冲突，系统应将该资产退回修整环节，对齐后重新送审。
9. WHEN 装饰完成度（放置家具数/宅基地可布置点数）首次达到 100%，系统应触发"最美庭院"高光广播。

### R6 工程地基（M6）

**User Story:** AS 开发者, I want 服务端模块化、可靠持久化、凭据安全与 LLM 降级, so that 后续功能迭代有稳定地基。

#### Acceptance Criteria

1. WHEN 服务端重构完成，afserver.mjs 应拆分为路由、世界模拟、账号、Agent 通道、市场、记忆六个模块，单文件不超过 800 行。
2. WHEN 世界状态或账号数据变更，系统应在 5 秒内以追加方式持久化到 SQLite，JSON 文件仅作为导出格式保留。
3. WHEN 服务进程崩溃重启，系统应从 SQLite 恢复到最近一次成功写入的世界状态，数据丢失窗口不超过 5 秒。
4. WHEN 仓库扫描发现明文凭据（token/密钥/密码），系统构建流程应报警并阻断合并，全部凭据改为环境变量注入。
5. WHEN LLM API 连续 3 次请求失败，系统应将该 Agent 切换到降级模式，按人设的 daily_pattern 以规则脚本驱动，直到 API 恢复连续 2 次成功。
6. WHILE Agent 处于降级模式，系统应在托管状态条显示"降级运行"标识并通知在线玩家。
7. WHEN 敏感配置加载，系统应从环境变量读取，环境变量缺失时启动失败并输出缺失项清单。

## Non-Functional Requirements

- 性能：8 名玩家 + 8 个 Agent 在线时，服务端单次 game_observe 响应时间不超过 500ms。
- 成本：单 Agent 每游戏日（10 分钟）LLM 调用成本不超过 0.05 美元，通过记忆压缩与小模型分流实现。
- 兼容：全部新视觉内容通过 client/mod/agentfarm.js 注入层渲染，原版 game/ 目录文件保持零改动。
- 许可：全部引入的第三方美术资产记录到 LICENSES 目录，仅接受 CC0/CC-BY（CC-BY 需署名清单）。
