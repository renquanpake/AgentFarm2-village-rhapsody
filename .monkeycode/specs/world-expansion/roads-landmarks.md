# 全图市政规划书（扩展 + 修路 + 地标 + 指引 + 特殊建筑）

Feature Name: world-expansion
Updated: 2026-09-30（范围升级：从村景单图 → 全 27 场景统筹；纯规划，未动工）
前置：`design.md`（+28 环零迁移坐标 + 生图建筑规格，已拍板）、`feasibility.md`（风险矩阵）

## 0. 总体规划原则

1. **全图一盘棋**：27 场景统一"轴系 + 地标 + 出口指引"模型，村景是枢纽节点（14 个门户），其他场景是卫星——每个卫星场景 = 一条进场主路 + 一个地标 + 一个返程出口指路牌。
2. **市政分层**：干道（穿村/穿场景主路，宽 2 格）→ 支路（到宅/到点，宽 1 格）→ 步道（活动区，无铺装）；路口有交叉语义（T 字/十字），路边有引导物（路牌/里程碑）。
3. **数据先行，画面跟进**：先落 `roads.json / landmarks.json`（导航 cost/语义层），再 shilu 图层克隆 + art-gen 路面贴皮（视觉层），最后 Cocos 反射挂路牌（指引层）。三层独立验收，画面缺了功能不断。
4. **Agent 可读**：所有市政设施进 observe regions（区域级：路名/地标/方向），Agent 的 move_to 优先贴路走（road kind 低 cost）。

## 1. 数据事实与现状差距

| 现状（代码） | 差距 |
|---|---|
| `NavKind = 0 空地 / 1 障碍 / 2 水 / 3 树丛`（navgen.ts:6），cost：空地 1 / 水 2 | **路（road）未建模**——TMX 有 `shilu` 铺装层、`onRoad()` 判定已存在（agentfarm.js:957），但 nav 里路=普通空地，Agent 不知"该走哪条路" |
| shilu 层只画在村区内部斑块 | 扩展环（+28）与新建筑街无路；27 卫星场景全无路数据（碰撞/水层已有，路无） |
| 门户 56 条 + 锚点（门/矿点）在 nav 数据里 | **无地标层、无方向指引**：到了路口不知道"河往东、矿往北"；小地图只有水/障碍/宅基地，没有路与地标图标 |
| `NpcPois` 只有村中心/河边/矿点/家门 4 类 | 市政扩展后 POI 应挂到路口/地标（银行岗亭/驿站），日程系统跟着活 |
| 生图 60 件（家具）+ 建筑 300-305（design.md 规划） | 市政件（路面/路牌/纪念碑/驿站）未列（306+） |

## 2. 路（municipal roads）

### 2.1 nav 语义扩展

- `NavKind` 增 `4 = road`，cost = **0.8**（贴路比草地省 20% → A* 自然塑形走干道）；`road` 层数据源：
  - 村景：`shilu` TMX 层现成（克隆提取）+ 新环人工设计段（roads.json 定义折线）；
  - 卫星场景：roads.json 逐场景折线（1-3 条/场景，沿现有通道的市政化）。
- `roads.json`（新，全场景）：
  ```json
  { "2": { "roads": [
      { "id": "vein-main", "name": "东西主街", "width": 2, "line": [[x1,y1],[x2,y2],...], "links": ["vein-avenue"] },
      { "id": "vein-avenue", "name": "南北大街", "width": 2, "line": [[...]], "links": ["vein-main"] }, ... ] },
    "3": { "roads": [ { "id": "river-path", "name": "河堤路", "width": 1, "line": [[...]] } ] }, ... }
  ```
  折线沿线扩 width 格 → 写 kind=4；交叉口（links）处自动补全交叉格。
- 门禁：**路面不做碰撞**（路永远可走），路边护栏是碰撞——市政"红线"概念。

## 3. 地标（landmarks）

### 3.1 数据模型

`landmarks.json`（新，全场景）：
```json
{ "2": [
  { "id": "plaza", "name": "村广场", "type": "monument", "x": ..., "y": ..., "desc": "集市/节日所在地，村中心" },
  { "id": "bank", "name": "银行", "type": "building", "x": ..., "y": ..., "desc": "存取与计息" }, ...],
  "3": [ { "id": "stone-bridge", "name": "石桥", "type": "bridge", ... } ], ... }
```
type 枚举：`monument / building / bridge / fountain / tower / dock / gate / stall`。

### 3.2 村景地标清单（含新建）

| 地标 | 位置 | 形态 | art-gen |
|---|---|---|---|
| **村纪念碑**（新建，最高优先级） | 广场正中（现村中心） | 石碑 + 村徽 + "Agent 村 · 交易区→ / 河→东" 铭文（字=运行时 Label） | 1 件 |
| 交易大厅/银行/邮局 | 设计书既定 | 挂牌三件 | 300-305 内 |
| 驿站/公告亭 | 广场东南角 | 小木亭 + 告示板（A9 日报/告示的物理载体） | 1 件 |
| 4 处路口里程碑 | 5 路口中的 4 个 | 矮石柱 | 1 件 |
| 南环渡口 | 河湾西岸 | 木码头 + 系船桩 | 1 件 |

### 3.3 卫星场景地标

沿用 2.2 表"地标"列；每个场景 1 个，**优先用场景既有视觉焦点**（桥/亭/水车/龙柱），无焦点的补 1 件生图件（预计补 8-10 件小地标，306-315）。

## 4. 指引（三层递进）

| 层 | 载体 | 内容 | 通道 |
|---|---|---|---|
| L1 世界内 | 路牌 Sprite（art-gen 1 件 + 运行时文字 3 行） | 路口/出口处："交易区→ / 河→东 / 矿→北"（方向+距离格数） | Cocos 反射 |
| L2 小地图 | mapgrid 路/地标图层 | 路=浅色线、地标=图标（8 类 SVG 简笔，DOM 画）、玩家图标 | mod afMapBg 扩展 |
| L3 文本 | observe regions + move_to 返回 | "你在村广场：东 12 格河边（钓/浴），西 5 格交易大厅，北 30 格矿" | 服务端 additive |

- L3 是 Agent 智能线受益最大的一层：observe 输出区域级"当前 POI + 各方向最近地标"（D2 区域原则的市政化延伸），move_to 路线摘要带路名（"沿东西主街向东"）。
- L1 路牌文案数据在 landmarks.json 的 `signs: [{landmark, x, y, lines: [...]}]`，文字运行时渲染（同建筑招牌原则：图不带字）。

## 5. 与特殊建筑的关系（顺序）

```
阶段 P1a 数据层（2-3 天）：roads.json 全 27 场景 + landmarks.json + navgen kind=4
                            + observe regions 市政化 + 工具链（roads --check/--render）
阶段 P1b 村景落地（2-3 天）：干道 9 条 + 5 路口 + 纪念碑/驿站/里程碑 + 路口指路牌
                            + 小地图路/地标图层
阶段 P1c 卫星批量化（agnes 委托，3-5 天）：26 场景三件套初稿 + 主模型抽检 5 场景
阶段 P1d 建筑生图批量（并行）：design.md 300-305 + 市政件 306-316（里程碑/路牌/纪念碑/驿站/渡口/桥梁）
阶段 P2  特殊建筑功能层：交易大厅/银行/邮局/气象台/宴会厅/健身房/铁匠（按 design.md 排期）
阶段 P3  相机/边界 spike 后 +28 环开建（design.md §1 负区方案 + 新环 4 条路并入 P1a 数据）
```

**"注意考虑全部地图"的落实**：P1a 数据层一次覆盖 27 场景（roads/landmarks/signs 全量 schema + 逐场景条目），村景只是最先渲染的一张——后面每个卫星场景落地 = 只加渲染不加数据，全图一致性由 schema 保证。

## 6. 验收门

| 层 | 门 |
|---|---|
| 数据 | `gen-nav --check`（kind=4 后旧 210 例回放不回落）+ `tools/check-roads.mjs`（全场景路口连通：路端点必接路口或地标/门户，悬空路 0） |
| 导航 | A* 塑形验证：同起点同终点走干道 vs 穿草地路径成本差 ≥ 15%（road cost 0.8 生效）；move_to 路线摘要含路名 |
| 画面 | 小地图全图层（水/障碍/路/地标/玩家）一屏可辨；实机截图人审（村景 1 + 卫星 5） |
| 回归 | 八道门 + 5128 哈希零变更（全部演进层） |

## 7. 风险

| 风险 | 对策 |
|---|---|
| kind=4 cost 0.8 改变旧回放路径（210 例期望值） | 回放脚本支持"路径不同但可达/距离比 <1.1 即过"（nav-replay 现有 drift 模式加一档 road-tolerance） |
| 27 场景路折线初稿质量参差 | agnes 批量生成 + 主模型按"端点必接路口/地标/门户"机审 + render PNG 逐场景目审 |
| 小地图图层信息过载 | 分层开关（路/地标两层可独立显隐，DOM 小按钮） |
| 与 +28 环负区坐标交叉 | P1a 数据直接用负区方案坐标（design.md §1），路折线一次到位含新环段 |

## 8. 不做（本规划边界）

- 不做路面物理（车/马等载具）、不做道路升级系统、不做交通流量模拟。
- 卫星场景只加"路数据 + 地标 + 出口牌"，其内部玩法（矿洞/温泉等）零改动。
- 经济钩子（市场/银行参数）仍冻结至 M-B1 影子窗结束。
