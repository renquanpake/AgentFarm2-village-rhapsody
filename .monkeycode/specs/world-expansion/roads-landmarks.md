# 全图市政规划书（扩展 + 修路 + 地标 + 指引 + 特殊建筑）

Feature Name: world-expansion
Updated: 2026-09-30（v2：自审修订——A* 塑形定稿、卫星 nav 现状修正、口径清理）
前置：`design.md`（+28 环零迁移坐标 + 生图建筑规格，已拍板）、`feasibility.md`（风险矩阵）

## 0. 总体规划原则

1. **全图一盘棋**：27 场景统一"轴系 + 地标 + 出口指引"模型，村景是枢纽节点（14 个门户），其他场景是卫星——每个卫星场景 = 一条进场主路 + 一个地标 + 一个返程出口指路牌。
2. **市政分层**：干道（穿村/穿场景主路，宽 2 格）→ 支路（到宅/到点，宽 1 格）→ 步道（活动区，无铺装）；路口有交叉语义（T 字/十字），路边有引导物（路牌/里程碑）。
3. **数据先行，画面跟进**：先落 `roads.json / landmarks.json`（导航语义层），再 shilu 图层克隆 + art-gen 路面贴皮（视觉层），最后 Cocos 反射挂路牌（指引层）。三层独立验收，画面缺了功能不断。
4. **Agent 可读**：所有市政设施进 observe（区域级：路名/地标/方向），Agent 的 move_to 优先贴路走（路格专属塑形项，见 §2.1）。

## 2. 路（municipal roads）

### 2.1 nav 语义扩展（v2 定稿：A* 塑形方案）

- `NavKind` 增 `4 = road`。**路格塑形定稿**：`cost = 0.6`、**clearance 特判置 0**（跳过 `clearance*0.15` 避墙项）——若只改 cost 0.8，开阔地 clearance 项（可达 3.0+）会把 0.2 的 cost 差淹没，路塑形失效；特判后路格步代价 0.6 vs 草地 1~4，路成为强吸引通道。
- 启发式代价：切比雪夫 h（每步隐含 1）对 0.6 路格高估 → **wA* 有界次优**（界 ≤ 1.67），工程可接受；由此 **nav-replay 容差按"成本比"比较**（g 值比 < 1.1 即过），逐格路径序列允许漂移。
- 桥/水优先级：`road ∧ water` → kind=4、cost=1（桥面，比水 2 快、比陆路 0.6 慢）；`road ∧ blocked` → 非法，check-roads 报错。除显式桥段外，路折线禁止穿水/阻挡格。
- 负区裁剪：roads.json 允许含 +28 环负区段；gen-nav 对村景建格时**裁剪到当前网格边界**，环建成前不生效、建成即自动启用（数据一次到位）。
- `roads.json`（新，全场景）：
  ```json
  { "2": { "roads": [
      { "id": "vein-main", "name": "东西主街", "width": 2, "line": [[x1,y1],[x2,y2],...], "links": ["vein-avenue"] },
      { "id": "vein-avenue", "name": "南北大街", "width": 2, "line": [[...]], "links": ["vein-main"] }, ... ] },
    "3": { "roads": [ { "id": "river-path", "name": "河堤路", "width": 1, "line": [[...]] } ] }, ... }
  ```
  折线沿线扩 width 格 → 写 kind=4；交叉口（links）处自动补全交叉格；路段索引供 `roadOf(x,y)` 反查（L3 路线摘要用）。
- 路面红线：路格永不碰撞；路折线避让宅基地内环/农田格/水（除显式桥）；decor 点位生成跳过路格。
- 客户端口径：服务端 kind=4 村景老区数据 = **shilu 层提取**；客户端 `onRoad()`（shilu 或裸草地）口径保持不动（它只管 blocker 避让），两者语义差异在工具链注释里写明。

## 3. 地标（landmarks）

### 3.1 数据模型

`landmarks.json`（新，全场景）：
```json
{ "2": [
  { "id": "plaza", "name": "村广场", "type": "monument", "x": ..., "y": ..., "desc": "集市/节日所在地，村中心" },
  { "id": "bank", "name": "银行", "type": "building", "x": ..., "y": ..., "desc": "存取与计息" }, ...],
  "3": [ { "id": "stone-bridge", "name": "石桥", "type": "bridge", ... } ], ... }
```

type 枚举：`monument / building / bridge / fountain / tower / dock / gate / stall`。**与 trade-hall spec 合并点**：trade-hall 的 `/af/mapgrid` 新增字段统一收敛为 `landmarks` 数组（trade-hall 作为 id 之一），避免 mapgrid 出现 tradeHall/landmarks 双源；trade-hall spec 相应条目在开工时同步修订。

## 4. 指引（三层递进）

| 层 | 载体 | 内容 | 通道 |
|---|---|---|---|
| L1 世界内 | 路牌 Sprite（art-gen 1 件 + 运行时文字 3 行） | 路口/出口处："交易区→ / 河→东 / 矿→北"（方向+距离格数） | Cocos 反射 |
| L2 小地图 | mapgrid 路/地标图层 | 路=浅色线、地标=图标（8 类 SVG 简笔，DOM 画）、玩家图标 | mod afMapBg 扩展 + mapgrid schema 增 `roads/landmarks` 数组 |
| L3 文本 | observe + move_to 返回 | "你在村广场：东 12 格河边（钓/浴），西 5 格交易大厅，北 30 格矿"；move_to 路线摘要带路名（`roadOf` 反查） | 服务端 additive |

- L3 是 Agent 智能线受益最大的一层：observe 输出区域级"当前 POI + 各方向最近地标"，move_to 摘要"沿东西主街向东"。
- L1 路牌文案数据在 landmarks.json 的 `signs: [{landmark, x, y, lines: [...]}]`，文字运行时渲染（同建筑招牌原则：图不带字）。

## 8. 不做（本规划边界）

- 不做路面物理（车/马等载具）、不做道路升级系统、不做交通流量模拟。
- 卫星场景只加"路数据 + 地标 + 出口牌"，其内部玩法（矿洞/温泉等）零改动；碰撞源提取本身是演进书既有待办，本规划不重复立项。
- 经济钩子（市场/银行参数）仍冻结至 M-B1 影子窗结束。
