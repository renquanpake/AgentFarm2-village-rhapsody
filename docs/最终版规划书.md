# AgentFarm2 最终版规划书

## 0. 支柱与感受基线（2026-11-20 补）

下游所有 D/N/M-O 条都应能回链到下面四条支柱之一。每条新增内容须回答「强化哪条支柱 + 删掉会失去什么」。

**四条产品支柱**（取自旗舰进化书 §0）：
1. **自主生活村庄** —— Agent 在村里起居/规划/赶集/社交/经营，由模拟变为真实。
2. **共享世界多人共居** —— 多玩家多 Agent 同处一村，经济/社交/事件流真实发生。
3. **复制壁垒四件套** —— 事件溯源 + 双档 LLM 路由 + 影子经济 + 评测集。
4. **原版载体零学习成本** —— Agent 行为落在熟悉的原版画面上，玩家 0 学习感知「它在生活」。

**玩家感受锚点**（P0/P1 交付收束标准，至少命中其一）：
- 看着原版角色按它的意思在走，不是被推着走。
- 它把我的指挥当回事，但不被我打断节奏。
- 我的角色和它的角色同处一村，能看见彼此做的事。
- 它做的事有连续性——昨天种今天浇，明天收。

## 1. 产品目标

**玩家应感到**：托管在线时主角按它的意思在走，不是我推的；每次出发都有一条看得见的路线；到达后动作自然衔接；打断它会停下回应，恢复后从真实位置重走原路。

**工程约束**：一个账号只有一个可见角色。玩家或 Agent 托管该角色时，游戏画面中的原版人物、原版走路动画、碰撞和相机必须保持一致。Agent 的每一次出发都应先规划可达路径，沿路径真实走动，到达后再执行钓鱼、种地或交互。

**原版取用边界**（README 第 3 行只声明了「剧情已去除」，下列矩阵补齐显式边界，避免后续各自演化）：

| 原版系统 | 取 | 改 | 不取 | 一句话理由 |
|---|---|---|---|---|
| 画面/地图/角色/碰撞/走路动画 | 全取 | — | — | 零学习成本载体 |
| 剧情线 | 不取 | 已去除 | — | Agent 联机题材与原版剧情冲突 |
| 经济系统 | 部分取 | 价格表+物品沿用 | NPC 自动价格循环 | 原版经济无法支撑多玩家真实交易 |
| NPC 系统 | 部分取 | 26 名 persona 保留 | 原版日程 | 服务端接管日程以驱动联机行为 |
| 室内场景/家具 | 不取 | — | 本阶段不做（§8） | 权威导航图稳定前不引入新场景类型 |

## 3. 当前故障定义（已收口）

### 3.1 角色不在画面中心 ✅ 收口（D1/D4）
根因：原版镜头/角色/客户端/服务端未以同一段「已确认路径」推进。现已改为航点级确认闭环：每段结束客户端回报真实落点，服务端校验通过才下发下一段；玩家打断经 AbortController 硬停（200ms 门实测），恢复后从真实位置重规划。

### 3.2 乱走和卡树（D2/D3）——代码侧已收口
权威导航图（nav-*.json）含 kind/cost/clearance；observe 输出区域级障碍（水域/树丛区域名 + bbox + 绕行原则，无单树坐标清单）；交互环 snapInteraction（水边/NPC/障碍外一格吸附），目标不可达不再直接报错而是吸附后重规划。
**状态口径（与旗舰书 §6 统一，2026-11-20 裁决）**：代码侧 ✅；自动行为验证已绿（nav-replay --smoke + drift 双跑、e2e-nav-arrive、nav-audit 违规 0）；人工实机判读挂 G2 阶段零统一验收。

## 4. 最终导航设计

### 4.1 一张权威导航图

生成 `navigation-grid.json`，尺寸 189 x 173（扩展村景，含 P3 外圈 +28 环）。每格除了 `blocked` 外还包含：

- `kind`: `road`、`ground`、`water`、`building`、`tree_zone`、`edge`。
- `cost`: 路最低，普通地面其次；禁止区域不可进入。
- `clearance`: 到障碍区域的最短格距。

这张图从 TMX 地图、建筑矩形、树丛区域和原版有效碰撞测试生成。服务端 BFS、客户端障碍注入、Agent 观察文本都从它派生，禁止三套规则各自演化。

### 4.2 区域级障碍，不给 Agent 树坐标清单

树和树篱应作为矩形/多边形区域，并向外膨胀 1 至 2 格安全边距。Agent 只读区域名称、格子范围和绕行原则，例如“宅基地 #5 树丛缓冲区，gx 54-62、gy 61-72，禁止穿越”。Agent 不需要也不应背诵单棵树坐标。

### 4.3 出发前规划，逐段确认

```text
收到目标
  -> 将目标吸附到最近可站立格
  -> 在权威导航图上 A* 规划完整路径
  -> 压缩为转弯点/安全航点
  -> 下发一个航点
  -> 客户端原版角色走到航点
  -> 客户端确认真实落点与状态
  -> 服务端校验后下发下一个航点
  -> 到达目标邻近可交互格
```

不能再按固定 120ms 盲推坐标。任何一次确认失败、碰撞回退、偏差超过半格、场景变化或玩家打断，都必须停止在 `STAND`，从真实位置重新规划。

### 4.4 镜头与角色状态

- 只让原版 `PlayerItem.changeDir()` 驱动移动和动画。
- 每个航点结束显式 `changeDir(INVAIL)`，保持 `STAND`。
- 客户端确认当前 `playerNode`、`sceneType`、相机目标仍为同一主角后才接受下一航点。
- 若目标不在当前场景，先调用原版场景通道；场景加载完成后重新规划，禁止跨场景直线移动。

## 5. 交互目标规则

钓鱼、NPC、树、农田和矿点都不以物体中心为目标。导航目标应是“目标周围的可站立交互环”：

- 钓鱼：水边相邻可走格，面向水面。
- NPC：NPC 碰撞范围外一格。
- 树/建筑：障碍缓冲区外一格。
- 农田/矿点：服务端判定半径内的最近可站立格。

## 7. 验收标准（数据基线：e2e-nav-arrive / nav-replay，2026-10-03 复核）

- ✅ 从任意宅基地到河边，先显示完整路线摘要，再稳定走到水边；途中不撞树、不穿水、不进入建筑（CI 门6 48 例零漂移，nightly 240 例零漂移）。
- ✅ 每次移动都有原版走路动画（changeDir 驱动），停下后进入待机；相机跟随为主机侧实机项（N2）。
- ✅ 玩家打断后 200ms 内停止（E2E 门实测 done 广播时序）；恢复后从真实位置重新规划。
- ✅ 同一条路线连续执行 10 次到达同一交互环（nightly `--matrix`：10 次 x 8 起点 x 3 路线 = 240 例）。
- ✅ 偏差超限会从真实位置重规划（drift 模式进 CI 门6 与 nightly，D1 闭环有自动门）。
- ✅ Agent 只得到区域级风险说明和推荐目标（observe obstacleRegions，无单树坐标清单）。

## 8. 本阶段不做

- 独立室内实例和家具系统。
- 全地图逐树语义标注。
- 让模型自行猜测障碍或逐键操作。

这些内容只有在权威导航图和航点确认稳定后才进入后续规划。
