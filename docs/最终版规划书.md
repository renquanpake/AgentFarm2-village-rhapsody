# AgentFarm2 最终版规划书

## 1. 产品目标

一个账号只有一个可见角色。玩家或 Agent 托管该角色时，游戏画面中的原版人物、原版走路动画、碰撞和相机必须保持一致。Agent 的每一次出发都应先规划可达路径，沿路径真实走动，到达后再执行钓鱼、种地或交互。

## 2. 已完成并验证

| 能力 | 当前结论 |
|---|---|
| 账号与角色 | 一个账号对应一个主角存档；托管不创建第二个 Agent 化身。 |
| 托管画面 | `agent_move` 已改为调用原版 `PlayerItem.changeDir()`，可触发原版走路状态机。浏览器冒烟测试确认主角节点会移动。 |
| 本地输入 | 托管在线时已拦截方向键和 WASD，并停止普通位置回传，避免与 Agent 位置竞争。 |
| Agent 生命周期 | 服务端可启动/停止托管子进程；未配置模型时明确失败，不再显示假在线。 |
| 模型供应商 | OpenCode Go 已确认可用：`https://opencode.ai/zen/go/v1`，模型 `deepseek-v4-flash`，接口为 OpenAI 兼容 `chat/completions`。 |
| 地图 | 村庄扩展为 105 x 89 格，小地图已可渲染扩展底图。 |
| 基础玩法 | 服务端已有移动、钓鱼、种植、收获、砍树、挖矿、购买和聊天判定。 |

## 3. 当前故障定义

### 3.1 角色不在画面中心

这不是简单的坐标问题。原版镜头、角色节点、客户端场景和服务端路径没有以同一段“已确认路径”为单位推进。服务端发出下一格后，客户端可能尚未真正抵达、被物理碰撞推回，或在场景/镜头状态未稳定时继续收到下一步，造成画面中心感丢失和视觉跳变。

### 3.2 乱走和卡树

当前 BFS 只使用一份粗略碰撞网格，并以固定频率推进；它没有把原版物理碰撞后的真实落点回传为下一步的起点，也没有使用“树丛/建筑群”这类区域禁行知识。因此逻辑路径可能穿过客户端实际存在的树、树篱或碰撞边缘，之后角色原地挤压或偏离路线。

## 4. 最终导航设计

### 4.1 一张权威导航图

生成 `navigation-grid.json`，尺寸固定 105 x 89。每格除了 `blocked` 外还包含：

- `kind`: `road`、`ground`、`water`、`building`、`tree_zone`、`edge`。
- `cost`: 路最低，普通地面其次；禁止区域不可进入。
- `clearance`: 到障碍区域的最短格距。

这张图从 TMX 地图、建筑矩形、树丛区域和原版有效碰撞测试生成。服务端 BFS、客户端障碍注入、Agent 观察文本都从它派生，禁止三套规则各自演化。

### 4.2 区域级障碍，不给 Agent 树坐标清单

树和树篱应作为矩形/多边形区域，并向外膨胀 1 至 2 格安全边距。Agent 只读区域名称、格子范围和绕行原则，例如“宅基地 #5 树丛缓冲区，gx 54-62、gy 61-72，禁止穿越”。Agent 不需要也不应背诵单棵树坐标。

### 4.3 出发前规划，逐段确认

```text
收到目标
  -> 将目标吸附到最近可站立格
  -> 在权威导航图上 A* 规划完整路径
  -> 压缩为转弯点/安全航点
  -> 下发一个航点
  -> 客户端原版角色走到航点
  -> 客户端确认真实落点与状态
  -> 服务端校验后下发下一个航点
  -> 到达目标邻近可交互格
```

不能再按固定 120ms 盲推坐标。任何一次确认失败、碰撞回退、偏差超过半格、场景变化或玩家打断，都必须停止在 `STAND`，从真实位置重新规划。

### 4.4 镜头与角色状态

- 只让原版 `PlayerItem.changeDir()` 驱动移动和动画。
- 每个航点结束显式 `changeDir(INVAIL)`，保持 `STAND`。
- 客户端确认当前 `playerNode`、`sceneType`、相机目标仍为同一主角后才接受下一航点。
- 若目标不在当前场景，先调用原版场景通道；场景加载完成后重新规划，禁止跨场景直线移动。

## 5. 交互目标规则

钓鱼、NPC、树、农田和矿点都不以物体中心为目标。导航目标应是“目标周围的可站立交互环”：

- 钓鱼：水边相邻可走格，面向水面。
- NPC：NPC 碰撞范围外一格。
- 树/建筑：障碍缓冲区外一格。
- 农田/矿点：服务端判定半径内的最近可站立格。

## 6. 实施顺序

1. 生成并可视化权威导航图，先人工核对河流、建筑和树丛区域。
2. 替换 `move_to` 为 A* 加安全代价和航点压缩；保留旧 BFS 仅作调试对照。
3. 增加客户端“航点到达确认”和偏差重规划协议。
4. 接入原版场景切换与每日醒来地点规则。
5. 扩展 `game_observe` 和 Agent 指南，暴露区域级障碍、推荐航点和目标交互环。
6. 加入路线回放测试：从每个宅基地到河边、村中心、矿点，各跑一次；验证无碰撞、无原地抖动、相机持续跟随。

## 7. 验收标准

- 从任意宅基地到河边，先显示完整路线摘要，再稳定走到水边；途中不撞树、不穿水、不进入建筑。
- 每次移动都有原版走路动画，停下后进入待机；相机始终跟随主角。
- 玩家打断后 200ms 内停止；恢复后从真实位置重新规划，不继续旧直线。
- 同一条路线连续执行 10 次，均到达同一交互环，且没有卡死或坐标漂移。
- Agent 只得到区域级风险说明和推荐目标，不依赖单树坐标。

## 8. 本阶段不做

- 独立室内实例和家具系统。
- 全地图逐树语义标注。
- 让模型自行猜测障碍或逐键操作。

这些内容只有在权威导航图和航点确认稳定后才进入后续规划。
