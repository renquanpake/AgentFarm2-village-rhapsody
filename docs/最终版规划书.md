# AgentFarm2 最终版规划书

## 1. 产品目标

一个账号只有一个可见角色。玩家或 Agent 托管该角色时，游戏画面中的原版人物、原版走路动画、碰撞和相机必须保持一致。Agent 的每一次出发都应先规划可达路径，沿路径真实走动，到达后再执行钓鱼、种地或交互。

## 3. 当前故障定义（已收口）

### 3.1 角色不在画面中心 ✅ 收口（D1/D4）
根因：原版镜头/角色/客户端/服务端未以同一段「已确认路径」推进。现已改为航点级确认闭环：每段结束客户端回报真实落点，服务端校验通过才下发下一段；玩家打断经 AbortController 硬停（200ms 门实测），恢复后从真实位置重规划。

### 3.2 乱走和卡树 ✅ 收口（D2/D3）
权威导航图（nav-*.json）含 kind/cost/clearance；observe 输出区域级障碍（水域/树丛区域名 + bbox + 绕行原则，无单树坐标清单）；交互环 snapInteraction（水边/NPC/障碍外一格吸附），目标不可达不再直接报错而是吸附后重规划。

## 4. 最终导航设计

### 4.1 一张权威导航图

生成 `navigation-grid.json`，尺寸 133 x 117（扩展村景）。每格除了 `blocked` 外还包含：

- `kind`: `road`、`ground`、`water`、`building`、`tree_zone`、`edge`。
- `cost`: 路最低，普通地面其次；禁止区域不可进入。
- `clearance`: 到障碍区域的最短格距。

这张图从 TMX 地图、建筑矩形、树丛区域和原版有效碰撞测试生成。服务端 BFS、客户端障碍注入、Agent 观察文本都从它派生，禁止三套规则各自演化。

### 4.2 区域级障碍，不给 Agent 树坐标清单

树和树篱应作为矩形/多边形区域，并向外膨胀 1 至 2 格安全边距。Agent 只读区域名称、格子范围和绕行原则，例如“宅基地 #5 树丛缓冲区，gx 54-62、gy 61-72，禁止穿越”。Agent 不需要也不应背诵单棵树坐标。

### 4.3 出发前规划，逐段确认

```text
收到目标
  -> 将目标吸附到最近可站立格
  -> 在权威导航图上 A* 规划完整路径
  -> 压缩为转弯点/安全航点
  -> 下发一个航点
  -> 客户端原版角色走到航点
  -> 客户端确认真实落点与状态
  -> 服务端校验后下发下一个航点
  -> 到达目标邻近可交互格
```

不能再按固定 120ms 盲推坐标。任何一次确认失败、碰撞回退、偏差超过半格、场景变化或玩家打断，都必须停止在 `STAND`，从真实位置重新规划。

### 4.4 镜头与角色状态

- 只让原版 `PlayerItem.changeDir()` 驱动移动和动画。
- 每个航点结束显式 `changeDir(INVAIL)`，保持 `STAND`。
- 客户端确认当前 `playerNode`、`sceneType`、相机目标仍为同一主角后才接受下一航点。
- 若目标不在当前场景，先调用原版场景通道；场景加载完成后重新规划，禁止跨场景直线移动。

## 5. 交互目标规则

钓鱼、NPC、树、农田和矿点都不以物体中心为目标。导航目标应是“目标周围的可站立交互环”：

- 钓鱼：水边相邻可走格，面向水面。
- NPC：NPC 碰撞范围外一格。
- 树/建筑：障碍缓冲区外一格。
- 农田/矿点：服务端判定半径内的最近可站立格。

## 7. 验收标准（数据基线：e2e-nav-arrive / nav-replay，2026-09-30）

- ✅ 从任意宅基地到河边，先显示完整路线摘要，再稳定走到水边；途中不撞树、不穿水、不进入建筑（27 场景 210 例回放零漂移）。
- ✅ 每次移动都有原版走路动画（changeDir 驱动），停下后进入待机；相机跟随为主机侧实机项（N2）。
- ✅ 玩家打断后 200ms 内停止（E2E 门实测 done 广播时序）；恢复后从真实位置重新规划。
- ✅ 同一条路线连续执行 10 次到达同一交互环（nav-replay 10 次 x 7 起点 x 3 路线）。
- ✅ Agent 只得到区域级风险说明和推荐目标（observe obstacleRegions，无单树坐标清单）。

## 8. 本阶段不做

- 独立室内实例和家具系统。
- 全地图逐树语义标注。
- 让模型自行猜测障碍或逐键操作。

这些内容只有在权威导航图和航点确认稳定后才进入后续规划。
