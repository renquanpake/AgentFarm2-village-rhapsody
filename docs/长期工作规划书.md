# AgentFarm2 长期工作规划书（2026-10-03）

## 0. 设计基线（用户定义，全文最高优先级）

**Agent 代理 = 玩家 AI 操控「屏幕内的小人」本身。**
`/agent` 通道发出的 move / move_to / chop / fish / plant 等一切动作，必须在游戏画面实时表现：位置移动、朝向、动作动画、行为飘字反馈。

判定标准：服务端动作生效了而打开的画面无对应表现 = P0 缺陷。
（本条优先级高于一切新功能开发。）

## 1. Phase P1 —— 小人移动与画面可视化（P0 之首：玩家确认「小人的移动是最关键的」）

### 1.0 前置：导航障碍数据完整性审计（「有障碍的坐标一定要全」）

寻路出错的根因几乎都是**障碍坐标没登记全**。P1 第一步先把数据面钉死：

- 新工具 `tools/nav-audit.mjs`（全量清点，进 CI 防回归）：
  1. **枚举所有阻挡来源**：buildings.json 建筑 rect（气象台/健身房/铁匠铺/广场环岛…）、home-slots/home-collision 宅地基、roads 路缘、水面/河流、mine-spots 矿山体、扩展区栅栏、宴会厅实体、场景边界、节日设施。
  2. **权威对照**：逐格重算服务端实际判定（walk()/blockedAt() 同款逻辑，按场景全图，场景 0/1/2/102…），与声明数据做集合 diff。
  3. **输出**：每场景阻挡格全集清单 + 来源归属 + 「实际阻挡但未入任何声明数据」的漏网格报告（目标：漏网格 = 0）。
- `move_to` 寻路失败文案必须**点名挡住的具体坐标**（如「前方 (65,54) 为建筑阻挡，建议绕行」），Agent 与玩家都可据此决策——配合 hpath 的交互环吸附，保证「目标 → 邻接可站格」映射始终存在。
- `chop/plant/water/till` 等目标格动作：执行前先校验邻接可达环非空，否则给 move_to 建议（杜绝「离目标太远/前方有障碍」式死胡同）。
- 门（portals，72 条场景 1 门户 + 跨场景门户）全部登记且双向可达复检。

### 1.1 已复现事实（真机截图测试）

### 1.1 已复现事实（真机截图测试）

- 客户端 `onAgentMove` 取节点路径单一：`__AF_MODS__.Application.getIns().playerNode`；实测场景加载后不同时机返回 `NONODE`/null → **消息被静默丢弃，画面永不动**。
- `act chop/fish/till` 等非移动动作：服务端只广播活动文案一行（publish），画面上无任何动画/飘字/标记。
- move_to 依赖原版 `changeDir` 走路状态机接管；状态丢失时无兜底插值。

### 1.2 修复设计

| 编号 | 内容 | 验收 |
|---|---|---|
| P1.1 | 节点获取冗余链：`getIns().playerNode` → `PlayerMoudle._gPlayer.node` → 场景树 find('Player') → 场景加载完成事件轮询；失败不丢弃，进入「最新态重放队列」，节点就绪时立即应用最新 `agent_move` | 任意时机开画面，角色位置 2s 内与服务端 agentPos 对齐 |
| P1.2 | 移动兜底：走路状态机接管失败 → 直接 `setPosition` 插值（150ms/段）+ 镜头跟随 | 连续 10 步 act move，画面坐标变化量 = 服务端变化量（±80px） |
| P1.3 | 动作可视化：chop/挖/种/浇/收/对话 → 角色姿态帧 + 头顶特效 + 行为飘字层（mod 注入，不动原版 5140 哈希壳） | 每类动作截图断言有对应视觉事件 |
| P1.4 | 指挥面板「此刻 agent 正在…」实时快照与托管在线状态灯（hostedAgentOnline） | 面板文案与服务端最近 1 条 agent 日志一致 |
| P1.5 | 双端验收工具：扩 `tools/shot-session.mjs`——act move/chop/move_to 三段断言（画面坐标变化、飘字出现、NONODE 时重放成功）；复现脚本即模板 | 门禁化，进 CI |

规模：中（全部在 `client/mod/agentfarm.js`，不触碰原版壳文件与 ui-lint 红线）。

## 2. Phase P2 —— 任务书 ×3（126 阶 → ~380 阶）

### 2.0 升级定位：游戏故事书（玩家明示要求）

任务书不只是清单，是**贯穿一年的村庄故事**：

- 每章开篇一段世界观引子（第 5 天开屏：村长递来村志空白册——与「村志」史诗链同源叙事）。
- 每条链有故事引子 + 尾声文案（NPC 口吻写进数据 fields：`intro`/`outro`），任务详情面板与完成推送都展示。
- 季节转章：第 11/21/31 天自动触发「换季信」（季节事件 + 新章解锁公告）。
- 终章「一年之约」完成 = 全村 NPC 贺词 + 村志合卷画面彩蛋（文案级，不动原版壳）。
- 「一环扣一环」既有机制（strict + requiresChain）继续作为故事推进主轴：**做完一个才推送同链的下一个**——客户端任务书面板将 active 阶段置顶高亮（未解锁链折叠在章节尾部）。

### 2.1 内容矩阵（设计先行）

保持「游戏内一年 = 40 天、四季四章」骨架，三层同时加密：

### 2.1 内容矩阵（设计先行）

- **a) NPC 个人任务线 ~12 链**：村长、木匠、梅姨、家石伯、二休禅师、明珠、屠夫、杂货店老板、树根嫂、赵香茹、飞英、护士……每人 4-6 阶小传（性格与台词进 `agent-personalities`/`npcs.json` 同源）。
- **b) 季节支线 ~8 链**：春·育苗aid/夏·防汛（storm 天气已有）/秋·囤粮冬·送暖（对接 season-events.json 16 事件的未挂钩项）。
- **c) 长线收集 ~4 链**：洒水器全家桶（77/78/79）、图鉴收集（鱼谱 65-76 八种）、关系网（bind/fav 全图）、委托信誉（delegate 系列）。
- 合计 ~24 新链 ≈ 260 新阶；总量 50 链 380+ 阶。

### 2.2 数值与节奏约束

- 全部 `strict` + `requiresChain` 环环相扣（引擎已具备，见 26 新链先例）。
- 奖励曲线对齐 N10 经济表：任务书总发放 ≤ 玩家 40 天产能的 1.5 倍（防通胀），金币物品交替发放。
- **40 天可完成性模拟器**：新工具 `tools/taskbook-simulate.mjs`——逐日推演可用链、可完成阶，输出日均曲线；红线：单日 5-20 阶之间，无断档、无井喷。
- type 值只使用已挂 taskCount 的 20 种（防「永不推进」缺陷复发，f1aa544 教训）。

### 2.3 交付批次

四季各一批（每批 ~6 链 65 阶 + 单测 + 走查），每批独立提交、独立回归（vitest/surface-audit/walkthrough/migration-rehearse）。

## 3. Phase P3 —— AI 接入提示词携带游戏规则

### 3.1 规则上下文构建器 `cognition/rules-prompt.ts`

从权威数据源**运行时**拼装（永不硬编码数值，改数据自动生效）：

1. 世界观一段（村庄四场景/槽位私有/40 天一年）。
2. 动作语义表：`act` 名 → 参数 → 返回，一行式（与 ws.ts act 全表同源，加 `--check` 门防漂移）。
3. 价格表摘要（economy-tables basePriceOf 三级口径 + NPC 收购 6 折）。
4. 地标与建筑坐标（landmarks/buildings，只列可导航 60 地标）。
5. NPC 名册（26 人：名字/岗位/tagline）。
6. 任务书摘要（taskView summary + 当前活跃链）。
7. 日历状态（今天第几天/季节/天气/节日）。

### 3.2 注入点与预算

- NPC 对话系统提示词（dialogue 主链）：完整版 ≤1200 token。
- 玩家自带 Key 的托管 Agent 大脑（game-agent.mjs 与 managed spawn）：完整版。
- 高频短路径（回信、闲聊）：精简版 ≤300 token。
- 反幻觉条款：「资料未写的，回答不知道」；行为一致性继续依托 agent-log recap。
- `rulesHash` 进对话日志归因；`GET /af/prompts`（admin token）现场查当前拼装结果。

### 3.3 验收

10 题探针集（价格/坐标/动作语法/NPC 位置/日历），对比未注规则基线的准确率显著提升；`eval-textonly` 扩 LLM 轮。

## 4. Phase P4 —— 新账号玩家视角新手教程

现状：`onboarding.json` 10 环是**服务端 Agent 视角**（教 AI 玩家用文本通道）；缺「人类玩家第一次开画面」的引导。两者并存、互不冲突。

### 4.1 设计：客户端 7 步引导（data/tutorial.json 驱动）

1. 认识你的小人与镜头（画面即世界）。
2. 走两步：键盘/触屏移动，画面实时反馈。
3. 打开 📜 任务书：看「新手村·日常」第一条（引出一年任务书与章节地图）。
4. 种一块地：till→plant→water→harvest 四连（作物 1 天生长时给「等明天」认知）。
5. 和 NPC 说句话（talk 问价/闲聊）。
6. **雇佣 Agent 替你干活**（呼应 P1：指令出去，小人真的在动——这是产品核心体验的教点）。
7. 完成第一单委托，收金币、开背包。

### 4.2 技术要求

- 步骤数据驱动 + 进度存 `afTutorial` 桶（登记 save key + 迁移注册，勿踩 `uid=''` 幽灵桶覆辙）。
- 浮层 UI 全走 AFUNI 组件与 token 样式（ui-lint 红线：裸色值 0、点击 100% AFUNI.on）；常驻 DOM 增量合规。
- 可跳过 / 任务面板「重看引导」可重放 / 5 分钟无进度自动收尾。
- 老账号永不弹窗（首次登录判定 + 存档位隔离验证）。

### 4.3 验收

真浏览器新号全流程走查工具记录完成路径；从注册到第一笔任务奖励到账 <10 分钟；ui-smoke 17 项 + 新增 3 项教程断言。
