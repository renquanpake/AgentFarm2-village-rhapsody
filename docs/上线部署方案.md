# 上线部署方案：GitHub 专属单房版

Updated: 2026-10-02
状态：**规划稿（暂缓执行）** —— 游戏未完工，本文档是完工后的执行清单。启动触发条件见 §7。

---

## 1. 定位（用户已拍板）

- 目标形态：**GitHub 专属版 = 一个链接、唯一锁定房间、2-3 名玩家、0 元成本**
- 与完整版的关系：同一个代码库，构建配置区分（Pages 版注入锁房参数），**禁止 fork 双维护**
- 成本结构：GitHub Pages（免费，客户端 + 链接）+ Oracle Cloud 永久免费层（免费，村庄进程）+ 用户自有域名（已具备，0 元）
- 社交形态：异步为主（信件/送礼/委托/八卦外显），Agent 即玩家的社交代理——2-3 人规模完全够用，全量广播架构在该人数下零优化需求

## 2. 架构

```
玩家（任何网络）
  │  打开链接
  ▼
play.<用户域名>  →  GitHub Pages（client/ 静态外壳 + mod，构建时注入官方服地址）
                        │  WSS
                        ▼
ws.<用户域名>  →  Oracle 免费层 ARM 机
                    ├─ Caddy（自动 TLS，反代 WebSocket）
                    ├─ Node 22（server/src/index.ts，systemd 常驻）
                    └─ data/（SQLite 事件库 + 存档，每日备份推私有仓库）
```

- 玩家视角：点链接 → 输邀请码注册 → 进村；Agent 24 小时托管
- 唯一房间由三处共同锁定：Pages 构建注入 `window.__AF_SERVER__`（钩子已存在，agentfarm.js:18）+ 隐藏「手动连接其他房间」入口 + 服务端注册邀请码与人数上限

## 3. 工作包（完工后执行，全部代码侧）

### WP1 服务端准入门（设计已定稿）
- `config.ts`：`AF_REGISTER_INVITE`（设值则注册必带邀请码）、`AF_MAX_PLAYERS`（账号总数上限，0=不限）
- `/af/register`：邀请码校验（403 带可执行提示）+ 账号数上限校验；`RegisterBody` 加可选 `invite` 字段
- 客户端登录表单加「邀请码（选填）」，随注册提交
- 测试：无码拒绝 / 有码通过 / 超限拒绝 / 上限内正常，四例

### WP2 客户端 GitHub 版
- 钩子已存在：`window.__AF_SERVER__` 优先级高于 location 推断（agentfarm.js:18-19）
- 构建时注入 `window.__AF_EDITION__='github'`，mod 据此隐藏 `#af-join-link`（手动连接其他房间）
- 登录表单邀请码字段随 WP1 落地

### WP3 Pages 发布链
- `tools/build-pages.mjs`：`client/` → `dist/`，注入官方服地址与 edition 标记，剔除开发文件（`_shots.html` 等）；`AF_OFFICIAL_SERVER` 未设置时构建失败（防呆，防止发出连不上自己的链接）
- `.github/workflows/pages-deploy.yml`：push master → build → deploy-pages（现有 ci.yaml、nav-replay-nightly.yaml 之外的第三条流水线）
- 一次性手动：仓库 Settings → Pages → Source 选 GitHub Actions；Actions 变量配 `AF_OFFICIAL_SERVER`

### WP4 Oracle 部署物料 `deploy/`
- `bootstrap.sh`：Ubuntu ARM 一条命令——Node 22（NodeSource arm64）、Caddy（官方 apt 源）、系统用户与目录、**iptables 放行 80/443**（Oracle Ubuntu 镜像预置 REJECT 规则，经典坑，见 §4）、systemd 安装、备份 cron
- `Caddyfile` 模板：域名一处填，`/ws`、`/agent` 反代 8080（WebSocket upgrade 自动透传）
- `env.example`：`PORT` / `AF_SLOT` / `AF_DATA_DIR` / `AF_AES_KEY` / `AF_ADMIN_TOKEN` / `AF_REGISTER_INVITE` / `AF_MAX_PLAYERS`
- `backup.sh`：`data/` 打包轮换保留 30 天（可选：推私有仓库异地）
- `UPGRADE.md`：升级（git pull + 重启）/ 回滚 / journalctl 看日志 / 健康检查 / 存档恢复步骤

执行顺序 WP1 → WP2 → WP3 → WP4，预计 1-2 个工作日（含 Oracle 注册排队时间）。

## 4. Oracle 免费层要点

| 项 | 说明 |
|---|---|
| 机型 | `VM.Standard.A1.Flex`（Ampere ARM），免费额度 4 OCPU / 24GB；本项目 2C / 8G 绰绰有余 |
| 系统 | Ubuntu 22.04/24.04 aarch64；Node 22 有官方 arm64（纯 TS + node:sqlite，无原生依赖障碍） |
| 公网 IP | 控制台 Reserve Public IP 并绑定实例，防重启漂移 |
| 两层防火墙 | VCN Security List（控制台放行 80/443）+ 宿主 iptables（Oracle 镜像预置 REJECT，bootstrap 处理）——**只开一层会白屏** |
| Keyvault | `openssl rand -hex 32` 生成 `AF_AES_KEY`（玩家自带 Key 的加密保管） |
| 闲置回收 | Always Free 实例连续空闲（CPU<20% 等画像）7 天可能被停，停前有邮件告警；2-3 名真实玩家日常登录 + 日历 tick + 每日备份，不会命中回收画像 |
| 注册门槛 | 需国际信用卡验证（不扣费，验证用），审核有失败率；区域选新加坡/日本/韩国离国内近 |

## 5. 用户操作清单（届时）

1. 注册 Oracle Cloud → 开 A1 实例（Ubuntu ARM）→ 保留并绑定公网 IP
2. 域名两条记录：`play` → GitHub Pages（或把自定义域绑到 Pages）、`ws` → Oracle IP
3. 机器上 `git clone` 仓库 → `bash deploy/bootstrap.sh` → 按提示填域名与邀请码
4. GitHub 仓库 Settings：Pages 源选 Actions，配 `AF_OFFICIAL_SERVER` 变量
5. 把 `play` 链接 + 邀请码发给朋友

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| Oracle 回收实例 | 停机前邮件预警；git 备份在，新机跑 bootstrap 十分钟重建 |
| 脚本党注册刷资源 | 邀请码 + 人数上限两道门；上线后盯注册速率 |
| Pages 与 ws 版本漂移 | Pages 随每次 push 自动重发；ws 侧 git pull 即新版；协议 zod passthrough 向后兼容 |
| 单点故障 | 事件溯源 + 每日异地备份；重建流程固化在 bootstrap |
| 2-3 人之外突然爆火 | `AF_MAX_PLAYERS` 兜底；超员再按旗舰书路线评估扩容（先扩配置后分片） |
