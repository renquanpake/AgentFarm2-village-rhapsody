## 0. 战略定位

**品类机会**：本作唯一的世界级潜力是 **Agent 托管的自主生活村庄**——LLM 驱动角色自主起居/规划/赶集/社交/经营，市面无此品类；事件溯源 + 双档 LLM 路由 + 影子经济 + 评测集构成复制壁垒。

**v2 新增支柱：共享世界多人村庄**。架构实测已有八成（单进程单世界、世界变更广播、角色私有分层），补齐住宅/确定性/原子性后，**多个玩家的多个 Agent 共处一村**，经济、社交、事件流全部由模拟变为真实。这是"自主生活村庄"品类成立的前提，也是与其他单机农场游戏的分水岭。

**战略结论**：
1. 资源倾斜：智能线（联机村+Agent 行为质量）> 体验线 > 内容量 > 画面量级。
2. 里程碑「100 陌生人中 30 个玩满 2h、10 个留存」**需要度量基建才能判定**——留存埋点/漏斗列为本书 N8，部署后随上线落地。
3. 2h 留存需要内容量支撑：当前新手第一天可玩完全部内容（审计结论），内容扩容立项为 N9。
4. 上线形态：GitHub 专属单房版（一个链接、唯一房间、2-3 人、0 元），方案固化于 `docs/上线部署方案.md`。

## 1. 收口标准（全书统一双标）

- **代码侧 ✅ + 行为验证 ✅ 才算收口**；仅有代码侧的条目标注「代码侧收口（待行为验证）」。
- 行为验证手段（制度化）：真实 `/agent` 通道实测、`tools/shot-client.mjs` 真实浏览器截图判读、压测脚本（并发/流量驱动）、事件重放一致性校验、f4-acceptance 六项。
- v1 教训：D1 曾标收口，行为验证发现 60 格硬上限拦截长路线——代码写了等于没闭环。

## 2. 质量基建（v2 新增章）

1. **玩家视角审计常态化**：`tools/player-cli.mjs` + 隔离 slot 实例 + LLM 子 Agent 完整游玩挑刺；每个里程碑收尾跑一轮，产出进缺陷流。
2. **真实客户端截图判读**：puppeteer + CJK 字体 + 图像理解（`tools/shot-client.mjs`），UI 文案/布局/重复元素可回归——v1 期间借此抓出 3 个 UI 真 bug。
3. **审计驱动缺陷流**：发现 → 修复 → 回归测试锁定 → tasklist 登记。阶段计划只管大方向，缺陷随到随修。

## 3. 数据契约与经济总账门（v2 新增章）

1. **存档键审计门**：`WORLD_KEYS/PLAYER_KEYS/GLOBAL_KEYS` 注册表与代码实际用键的一致性检查工具化并进 CI。教训：`bucketOf` 对未注册键返回 null 曾静默丢弃 `sprinklerData`/`livestockData`（P0，已修 6f50bf6）；任何新世界桶必须登记。
2. **经济总账门**：产出速率 vs 回收速率（10% 手续费 + 各消耗口）周期对账；`/af/economy` 增净流入指标；通胀超阈值告警。v1 的 M-B1 只管市场微观结构，不管通胀。
3. **采集动作约束**：采集类产出必须有冷却或消耗（chop 例外：树 HP 天然有限）；修法以 `world/stamina.ts` 为范式。

## 4. 性能预算（v2 新增章）

- 广播：单条 `save_broadcast` 体积监控，>256KB 告警；分片预案 = 56x56 住宅区块（只记不做，等数据说话）。
- 确定性：10 账号灰度下事件重放哈希稳定。
- 容量口径：单进程 SQLite，2-3 人零压力，10 人灰度实测，50 人再议分片。
